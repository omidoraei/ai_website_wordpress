# 03 — Kit document (`site-settings`) controls

The design system ships as an Elementor **Kit** document:
`templates/kit/aurora-site-settings.json`, generated by `tools/aurora/kit.py`, exported as
`dist/aurora-ai-kit.zip` + `dist/site-settings.json`.

Provenance: `elementor/elementor@v3.35.9`, `core/kits/documents/tabs/*` — 13 files, all
indexed in `references/_generated/control-index.md` under "Kit site-settings tabs".
`global-colors.php` and `global-typography.php` each gained one `do_action` line in v4.0.8;
no control changed (see `04-version-deltas.md`).

**Kit control ids follow the same rules as widgets**: a control in tab file `X` is stored in
the kit document's `settings` under the id the file registers, and a control *group* expands
to `<name>_<field>`.

## 1. Global colors — the reliable part

```json
"system_colors": [ { "_id": "primary", "title": "Amber", "color": "#F4A62A" }, … ],
"custom_colors": [ { "_id": "sand-50", "title": "Sand 50", "color": "#FFFBF5" }, … ]
```

| Rule | Detail |
| --- | --- |
| `system_colors` must be **exactly four** rows | the ids `primary`, `secondary`, `text`, `accent` are what Elementor's theme-style controls reference |
| Every row needs `_id`, `title`, `color` | `title` is the label shown in the picker |
| Colours are **solid hex only** | a translucent value (`rgba(...)`) cannot be bound as a global; the kit therefore keeps `rgba(255,255,255,0.12)` as a token that is written directly onto the element, not as a global |
| Reference form | `"globals/colors?id=<_id>"` — an id that is not defined by the kit is a build failure (`tools/verify.py`) |

## 2. Global typography

```json
"system_typography": [ { "_id": "primary", "title": "Headings",
                         "typography_typography": "custom",
                         "typography_font_family": "Sora",
                         "typography_font_weight": "600",
                         "typography_font_size": { "unit": "px", "size": 42 },
                         "typography_font_size_tablet": { … },
                         "typography_line_height": { "unit": "em", "size": 1.15 },
                         "typography_letter_spacing": { "unit": "px", "size": -0.6 } }, … ]
```

| Rule | Detail |
| --- | --- |
| Field prefix | `typography_` — the group in `global-typography.php` is named `typography` |
| `typography_typography` | holds `"custom"` (not a global reference: a global cannot reference a global) |
| Per-breakpoint | `typography_font_size_tablet` / `_mobile` are valid and are how the FA styles carry their own sizes |
| Reference form | `"globals/typography?id=<_id>"` on any element's typography group |
| `system_typography` should be four rows | `primary`, `secondary`, `text`, `accent`; everything else goes in `custom_typography` |

## 3. Layout

| Key | Value shape | Kit value | Notes |
| --- | --- | --- | --- |
| `container_width` | slider | 1240 px | the boxed container width |
| `container_padding` | dimensions | responsive | default inner gutter |
| `space_between_widgets` | gaps | default | |
| `default_page_template` | select | `elementor_canvas` / `elementor_header_footer` | |
| `active_breakpoints` | list | `viewport_mobile`, `viewport_tablet` | which breakpoints are on |
| `viewport_md`, `viewport_lg` | number | 768, 1025 | **legacy breakpoint keys** — still read by 3.x; newer versions use the `active_breakpoints` + custom-breakpoint system |
| `breakpoints_updated` | switcher | — | set by the panel when breakpoints are customised |

## 4. Theme style

* Typography tab: `body_typography` (group), `link_normal_typography`,
  `link_hover_typography`, and one group per heading level (`h1_typography` … `h6_typography`).
  The kit's ladder lives here, so a heading that is *not* bound to a global still looks right.
* Buttons tab: `button_typography`, `button_background_color`, `button_text_color`,
  `button_hover_color`, `button_border_radius`, `button_padding`, plus the
  `button_background_hover_*` and `button_hover_box_shadow_*` groups.
* Form fields tab: `form_label_typography`, `form_field_typography`,
  `form_field_background_color`, `form_field_border_*`, `form_field_focus_*`,
  `form_field_padding`, `form_field_border_radius`.

## 5. What the kit deliberately does NOT set

| Not set | Why |
| --- | --- |
| `customCode` / custom CSS tab | rule 2 |
| `experiments` | changing a site's experiments from a kit import is a hostile side effect |
| `customIcons`, `customFonts`, `classes`, `variables`, `defaultStyles` | `variables`/`classes` are Elementor 4.x-only surfaces and were not verified; fonts are documented as a manual step (`docs/04`) |
| `site_logo` / `site_favicon` | site identity stays with WordPress; a kit must not overwrite a client's logo |

The exporter's `ALLOWED_SETTINGS` list is a superset of what this kit declares. Declaring less
is intentional: a kit that imports only what it documents is one whose effect you can predict.

## UNVERIFIED — do not emit

* Elementor 4.x `variables` and `classes` kit keys: no public behavioural source was reviewed,
  so nothing is emitted for them.
* `defaultStyles`: present in the export allow-list but its exact payload was not confirmed at
  this tag — not emitted.
* Any kit key whose name is not present in `references/_generated/control-index.md` §
  "Kit site-settings tabs". If you need it, re-run `scripts/extract_controls.py` first.
